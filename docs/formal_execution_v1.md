## 固定的首轮研究预算

| 分支/阶段 | 输入权重 | 数据预算 | batch × accumulation / length | 峰值LR |
|---|---|---|---|---|
| 198M从零预训练，正在运行 | 随机初始化 | 8,460,241训练记录，1 epoch；约19.20亿有效token | 6×24 / 512 | 3e-4 |
| 198M SFT，已排队 | 完成预算后的预训练best | 5,102,028非零监督记录，1 epoch；约30.50亿标签 | 2×8 / 1536 | 1e-5 |
| Hybrid新增线性模块适应 | 完成预训练best，经显式键/shape迁移 | 相同shuffle的前120,000记录，5,000 updates | 4×6 / 512 | 1e-4 |
| Hybrid全参数续训 | **适应阶段最后一步**，不是早期best | 完整预训练train split再1 epoch，352,511 updates | 4×6 / 512 | 1e-4 |
| Hybrid SFT | 完成续训后的固定验证best | 完整SFT train split 1 epoch，318,877 updates | 4×4 / 1536，重计算 | 1e-5 |
| 198M额外数据对照 | 与Hybrid相同的预训练best | 与适应、续训、SFT逐阶段相同样本顺序、预算、LR和checkpoint选择规则 | 对应Hybrid各阶段相同物理batch、累积、长度 | 同上 |

5000步只是迁移适应阶段的预注册预算，绝不是Hybrid的全部训练。新增模块约1782万参数在适应阶段更新；之后205M完整模型全部更新。新增模块没有训练过，1e-4是明确的初始recipe选择，不是已经证明最优的学习率。阶段初始/周期/末尾验证都保留；若不下降、非有限或缺少有效更新，队列停止并保存证据，需要诊断后新版本方案，不能自动减模型或略过。

与前一次资源选择相比，适应阶段从已测B8×3退到同样已测的B4×6，是为了与AR对照统一物理batch/MoE统计，预计牺牲约5%～6%的适应吞吐。正式原始198M预训练/SFT不修改。对照SFT选择已测B4重计算，与Hybrid一致；它比原主线B2慢，但减少物理batch差异。架构实验比较的是“迁移、适应、续训这套程序”，不是证明只有Attention一个因素改变：可训练参数集合、初始化和架构当然不同。

适应→续训使用最终第5000步导出，确保两条支路都真正接收120,000个样本更新。续训→SFT统一用固定验证best；如果两者最佳步数不同，要同时报告选择步数和最终权重结果，不能声称所选权重经历完全相同的更新历史。迁移与阶段衔接加载FP16导出至FP32并重建AdamW；阶段内resume保存FP32模型、AdamW、RNG和cursor，二者含义不同。

总样本呈现17,799,071。单卡有效batch128，T2A B16×8，A2A B2×64，I2T全参数B4×32/投影B16×8。长度T2A1536/A2A3072/I2T768；完整315M结构、8路音频head、冻结SenseVoice/SigLIP不变。A2A累积许多microbatch会把fbank留在主机内存，服务器充足RAM是选它的主要依据之一。

保留作者epoch/LR不等于严格复刻四卡算法：原建议每卡B32，路由aux统计与我们的microbatch不同；更长上下文、数据划分、warmup、确定的增强种子和选择best都是自有recipe。保留完整监督和评估是本实验目的，不能把它称作作者发布权重的精确重现。投影阶段不改变原作者20%文字回退策略，监控无输入模态/零监督比例；需要改变时另立recipe版本。

每阶段保存原始CE、8个音频head CE、STOP统计、梯度、吞吐、显存、host RAM/swap和checkpoint。阶段完成后重新生成已经学习模态的固定文字/音频/图像探针，保存原始codes/WAV以观察遗忘和恢复；没有自动语义质量合格判定。A2A未见录音与I2T未见图像划分按已有审计解释。

## 时间与执行方式

实际速率决定耗时。首个预训练剩余约两天，原始SFT约4.5天；Hybrid完整额外预训练按16.96样本/s估约5.8天，SFT按5.13样本/s估约11.5天。这里未含验证、保存、系统中断和故障诊断。Omni七阶段按不同输入路径的短测速率外推也属于**数周**规模，短测尤其长尾音频不能精确预测全量时间。

因此“前三项全部完整训练＋对照”与“几天内全部结束”不能同时保证。采用本机Hybrid、服务器Omni并行减少墙钟时间；不删数据/epoch、不缩模型来掩盖成本。若后续实测表明大部分重复epoch没有价值，应记录曲线和生成证据后调整，而不是现在无依据减少。

`tools/run_formal_pipeline.py`检查源代码/config指纹、完整阶段实际steps与数据量、最终全验证、训练过的best和恢复状态。失败会留下controller日志并停止相关分支；不杀其他任务，不自动重试OOM至成功，不覆盖旧run。控制器可用`--resume`重新检查已经完成的阶段，不重复训练。最终状态`pipeline_budget_complete`仍带`quality_review_pending=true`，所有模型质量和学习总结完成前不宣布整个项目完成。

接续进程在WSL/服务器当前会话中运行，不是开机服务；断电、WSL关闭或网络认证丢失后仍需要检查状态并恢复。不能把后台进程说成无人干预必定训成。所有正式参数改变必须生成新版本计划，旧来源与差异保留。

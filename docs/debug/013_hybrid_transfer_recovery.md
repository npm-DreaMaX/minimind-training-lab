# Hybrid 正式迁移后的高 loss：先保留现象，再检查能力恢复

对应运行：`models/02_hybrid_moe/runs/hybrid_adapt_official_full_v1/`。2026-10-03 从已验证的官方 198M 预训练权重迁移，完整205M模型，新增17,824,416参数独立适应。此记录仍在观察中，不能把早期loss下降写成问题已经完全解决。

## 现象

step 0 固定512条验证、123,368监督token的 CE 为 **9.997485**，生成有乱码、不成句。前3步训练CE约10，裁剪前grad norm约36；约300步训练CE降到约7，grad norm约2.6。训练记录没有NaN/OOM，所有指标与原始生成保留。

这里的norm是所有**可训练的新模块**梯度合并后的裁剪前L2范数。配置使用阈值1，实际optimizer拿到的梯度已裁剪。大于1不自动等于NaN或必须减batch；应结合是否持续飙升、有限性、验证变化和参数更新判断。

## 初始假设、检查与证据

## 当前诊断与处理

**工作假设是结构迁移后的能力恢复，不是已经确认的训练器故障。** 没有为了得到更好看的初值而把官方AR分数当成Hybrid分数，没有跳过step 0，也没有临时放弃6层线性注意力。当时计划继续5,000步新增模块适应，保持原学习率、裁剪、精度与随机样本顺序；14:05已保存暂停，后续路线更正见文末。

早期训练loss下降仅是积极信号，各步样本不同，不能直接用第1步和第300步作严格效果比较。固定验证使用相同512条样本、相同监督token计数，selection SHA为 `35a38ff957d0d37bf7a0ef4bd07dbd57a42a599826796aaa853fd82c2b8abbc7`。第500步后比较同一集合的CE与原始生成，才更能说明迁移在恢复。

## 后续观察与快速识别

若train与固定validation同步下降且梯度有限，可继续当前阶段；若训练下降但验证持续上升，检查拟合偏差和数据分布。若CE几乎不动，检查可训练参数名单、门/卷积/输出投影梯度与实际更新幅度；若出现非有限数，保留失败步和最近完整恢复点，再区分输入、精度与学习率原因。适应结束仍需比较能力恢复程度，不能只凭budget complete跳过质量分析。

## 第500步的复核：确实在学习，但生成还不合格

相同验证selection SHA、512条/123,368监督token下，CE从9.997485下降到 **6.078842**；该阶段已训练2,712,906个有效token。最近纯更新每步约1.1秒，有效batch24，显存峰值allocated 2,779,577,344字节。没有通过减模型或替换成小数据视图实现。

这支持「迁移后表征正在恢复」的判断，但不能说明已经足够：人工智能题能输出中文短句，首都和水状态题仍出现“想想想……”重复、答非所问并撞到64-token生成上限。原始输出见 `evaluation/step_0000500.json`，不挑选成功案例覆盖失败。

第500步检查时未因这一早期结果改学习率、增大batch或声称完成；该分支后来已保存暂停。第500步的独立快照在[首次快照目录](../../models/02_hybrid_moe/deliveries/20261003_first_500/)，保存完整恢复状态、全205M参数导出、同一步数评估、来源和SHA。这个捕获过程只用CPU，不占用训练GPU；18:00的同类捕获也不会停止训练。

首次快照的CPU完整性复核通过：189个state键与完整205M源码shape相符，54个线性模块tensor确实发生更新，135个保留tensor逐位未变；所有FP16导出值等于同一步恢复参数的half转换，embedding/head的共享权重数值一致。同一步评估确认为500步。报告见快照目录`artifact_verification.json`。这证明冻结/更新范围和交付文件真实，仍不证明生成质量合格。

旧分支已在1369步、7,446,025token处完整保存并暂停。第1000步固定验证CE4.763859仍不代表生成合格。后续改按作者已有SFT权重转换路线，初始化、数据与目标阶段改变，另建run，不能把两条曲线拼接成同一次训练。先前18:00捕获旧分支的进程已取消。参见[官方mini两轮方案](../hybrid_official_mini_2ep_v1.md)。


## 18:17：独立SFT分支的恢复与尚未解决的问题

当前 `hybrid_sft_official_mini_2ep_v1` 已超过8,000步。它从官方SFT基座重新迁移，全参数训练；与前面的冻结预训练适应分支不是同一run，不把两条loss曲线相连。固定512条/191,220标签的CE从10.7034连续降至8,000步2.7840，步数、有效token累积、scheduler、配置指纹和checkpoint均复核通过。

现象：语句比初期连贯，但仍重复；蓝天问题没有解释，17+25转而生成无效代码，三个greedy样例均达到64-token上限。初步假设包括新注意力仍在恢复表示、数据/目标分布与短问题不匹配、解码或缓存数值差异；现有下降曲线不足以区分所有原因。没有把“程序没报错”当作生成质量合格，也没有用反复调采样参数挑选好看的回答。

路由方面，第三层的非padding token向一位专家集中到约72%；末层最大占比则从约90%降到60%，部分专家低于1%。这是逐50步第一microbatch的抽样统计，官方aux还包含padding位置，不能把两者数值直接等同。全部专家仍被使用并不意味着负载理想；当前没有证据足以判定为全局路由塌缩或立即增大aux系数。

处理：保留完整两轮预算与现有LR/aux，继续记录固定验证、原始生成和分层路由。若CE趋平而生成持续失败，下一项有区分力的检查是对同一固定checkpoint/同一prompt比较完整forward与cache推理，并与官方AR基座在相同输入模板下比较；不能仅靠加轮数或改batch掩盖问题。尚未执行这组新的训练后cache对照，不提前宣布排除了它。

[本次完整检查](../../reports/hybrid_health_20261003_1815.md)保留曲线、样例、资源、快照SHA和判断边界。训练未中断，未改变数据/结构/预算。

## 20:00：训练后CPU缓存对照通过，质量问题仍未解决

现象：第12,000步固定验证CE已降至2.4323，但生成仍重复、算术答错。初始假设之一是缓存状态或位置偏移错误：teacher-forcing完整forward可以有较低CE，逐token缓存推理却可能出错。因此本次提前执行上节提出的cache对照，使用实际训练后的完整205M权重，不只复用随机初始化时的小测。

检查方法：将当时最新的第12,000步完整恢复文件硬链接到独立诊断目录，防止后续保存替换它；校验模型源码SHA，strict加载全部参数。只使用CPU、FP32、两个CPU线程，不占训练GPU。三个固定问题各生成32token，再将**完全相同的prompt和生成token**一次性送入完整causal forward，逐位置比较logits。若让两个路径自由生成不同输入，再比较logits，就会混入输入差异。额外使用137-token真实语言序列、126-token prefill，覆盖128位置边界。

证据：3条实际prompt与边界样例全部满足预设relative RMS<1e-3、max absolute<0.02；实际最大relative RMS为6.94e-7、最大绝对差1.77e-5，所有位置argmax一致。CPU FP32同样给出蓝天循环解释、错误的“15加9”算式。对照计算耗时3.05秒，不包含import和checkpoint加载。

排除范围：没有发现这些输入上的CPU cache/full-forward不一致，降低了明显状态更新/位置错误的可能性。**这不是GPU FLA/BF16数值复验，也没有排除数据分布、训练程度或其他模型问题。** 根因尚未最终确认，不能把缓存对照通过写成生成问题已修复。官方AR基座在同一组输入上的配对对照仍未在本轮执行。

处理与后续验证：无需缓存修复，没有改正式模型/数据/学习率/精度。第12,500步固定CE进一步降到2.4055，生成仍不合格；继续原两轮训练，观察固定验证、原始生成与分层路由。若后续CE趋平而自由生成仍失败，再检查相同权重的GPU与CPU推理、模板与官方AR配对对照。快速识别方法是把teacher-forcing指标和自由生成分开，再用相同序列的逐位置logits隔离缓存问题。

原始证据：[诊断目录](../../models/02_hybrid_moe/runs/cache_diagnosis_trained_cpu_v1/)、[工具源码](../../tools/check_hybrid_trained_cache_cpu.py)、[原始日志](../../logs/hybrid_cache_diagnosis_trained_cpu_v1.log)、[本轮运行/质量报告](../../reports/hybrid_health_20261003_2000.md)。

## 2026-10-04 14:09：接近半程，CE改善但自由生成仍不可靠

独立SFT分支已完成54,465/113,082步，固定512条验证在54,000步降到1.775915，109次评估含初始值均比前次下降，改善幅度正在减小。更新连续、token累加和配置指纹通过，未见非有限loss/gradient或OOM。不能将这一结论扩展为质量合格。

实际失败：自我介绍更连贯，却在已关闭的思考前缀之后再次输出`</think>`并重复介绍；蓝天问题泛谈天体，前两次还归因于地球自转轴倾斜；17＋25在53,000/53,500/54,000步分别输出70/174/35。三个64-token探针都没有EOS。这里应区分回答长度受预算限制、格式控制失败、事实/算术错误，不能一概归结为输出太短。

根因仍未确认。第12,000步CPU缓存对照的通过降低了该时刻这些样例的缓存语义错误可能性，但不能排除当前GPU数值路径、模板/训练数据格式或迁移能力不足。第3层路由集中程度较早期减轻，第7层一位专家仍低于1%，无法仅凭这些统计断言它导致全部生成错误。

本次保持完整两轮预算；没有为了改善样例临时调解码、改模板或aux系数。下一项应做有区分力的官方AR/Hybrid同模板同精度配对生成，覆盖更长输出预算和思考标签；本轮未执行，不声称已经排除这些因素。后续预算完成必须单独判定质量，不能把“多训练必然变好”当保证。[完整检查与进度](../../reports/hybrid_health_20261004_1400.md)。

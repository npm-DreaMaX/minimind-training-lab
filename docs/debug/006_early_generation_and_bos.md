# 预训练早期生成重复：不能只凭一个猜测改训练

第500步固定验证CE从8.8943降至3.5487，但“中国的首都是”仍重复“中国”，另两个提示也有低质量续写。对应已训练约1630万有效token，仅约一轮预算的0.85%。

初始假设包括：训练仍早、greedy生成暴露重复、评估缺少BOS与训练格式不一致。检查发现tokenizer没有自动BOS post-processor，训练缓存明确包含BOS，而当前运行中的预训练生成协议使用裸前缀。该差异值得控制实验，不能直接宣布是根因。

`tools/compare_generation_prefix.py`在CPU上加载第500步固定导出权重，保留SHA，比较同一提示的裸前缀与显式BOS。使用相同greedy方式、不添加重复惩罚。结果在`models/01_moe/runs/pretrain_full_v1/evaluation/prefix_protocol_cpu_step500.json`：BOS改变了续写内容，但仍出现重复和知识错误。因此不能把质量问题归因于缺少BOS，也不能用加强采样限制隐藏失败。

第1000步同一验证集合CE进一步降至2.8574，AI应用提示出现较合理续写，首都与水的状态仍失败。暂时没有NaN、持续梯度爆炸或显存异常证据，继续计划预算并观察同一评估协议。

当前GPU训练进程保留启动时的裸前缀协议，不热改其源码或混用前后指标。后续增加BOS版评估时独立标记协议版本，保留旧输出；SFT则使用chat template。此时尚无证据需要修复训练算法。

第1500步验证CE降至2.6354，但greedy重复仍存在。进一步排查缓存：`tools/check_ar_cache_cpu.py`加载当时的已训练198M权重，比较完整序列与逐token KV-cache logits，两条真实中文文本分别测试有/无BOS。四项均通过，最大绝对误差约5.01e-6，所有位置argmax相同。结果在`evaluation/cache_protocol_cpu_early.json`并记录checkpoint SHA。这排除了这些CPU输入上的明显cache数学错位；不把它泛化为所有长度、padding或GPU kernel都已验证。

以后遇到类似问题：先固定checkpoint、prompt、token IDs和解码参数，再一次只改变一个条件；同时检查held-out CE与生成。loss下降证明某种预测改善，不证明模型已学会所有知识或可靠对话。

## 第2750步、官方参考与统一BOS协议

新增prospective probes使用显式BOS、CPU FP32、greedy、相同token预算，对比本项目第2750步与固定版本官方pretrain。结果在本项目`evaluation/probes_step2750_cpu_v1/`及`models/01_moe/reference_evaluation/official_pretrain_cpu_v1/`。本项目加BOS后能够给出“北京”和部分AI应用词汇，但仍明显循环；官方预训练参考也会重复或给出错误事实。不能把旧无BOS输出与新BOS输出的差异全部归为训练进步，也不能只由本次六个例子给架构下结论。

官方SFT参考在相同CPU协议下运行了16条短探针，其中10条有严格格式评分，结果0/10。**这不是“数学能力0%”**：9条评分样本及14条总样本达到生成预算，其中算术只给32个new tokens；模型常先输出解释，已经违反“只输出数字”的格式，同时输出又可能被截断。需要把格式遵守、算术正确性和token预算分别分析。原始prompt已使用tokenizer默认闭合的空think前缀，没有要求模型开启思考。所有失败原文保留，未据此替代正式训练或扩大参数规模。
# 补充：延长官方SFT参考的生成上限

原协议保持不动，另存 `models/01_moe/reference_evaluation/official_sft_cpu_budget256_v2/`，对前9项算术/JSON题将每项生成上限提高到256。仍为严格格式0/9；其中5项正常EOS，4项仍达到上限。正常结束的加法输出17+25=45、减法83−47=23、运算优先级输出35，说明这些错误不能都归于32-token截断；除法输出12，但违反“只输出数字”且解释有误。完整输出、模板、解码参数与SHA均保留。

这是9题具体探针，不能推广为模型全部任务准确率，也不是我们的训练结果。它支持后续把“正确性、格式遵循、终止和重复”分别评估；若增加我们自己的数据，优先考虑可程序验证的算术/结构化输出，并以独立对照和通用数据回放研究收益与遗忘，不把扩大参数量当作自动解决方案。

## 后续进程使用周期生成协议v2

完成独立BOS/缓存对照后，`lab/train.py` 的后续启动进程显式加入预训练BOS，记录input IDs、rendered input、EOS与预算截断；greedy参数全部显式给出，记录 `generation_protocol.version=2`。当前已运行的3502步恢复进程仍使用其启动副本，下一次恢复才生效。旧输出没有改写，缺少version字段的旧记录按v1裸前缀解释。新旧生成内容不能直接作为训练改进比较。

此修改不改变训练样本、CE、aux、backward或优化器，也不改变teacher-forced验证集合/分数；评估前后恢复RNG。输入ID检查见 `reports/periodic_generation_protocol_v2.json`。它修正格式一致性与可观测性，不保证模型从此不重复。

第3502步的同协议CPU六题探针在 `evaluation/probes_step3502_cpu_v1/`：AI应用开头列出自然语言处理/图像识别等，但随后重复；首都错误地续写为华盛顿；小猫故事能EOS结束但仍循环。六项中五项达到生成预算。与2750步相比并非每一道固定题都变好，不能只挑“北京”那一次展示，也没有证据仅靠重复惩罚即可修复事实错误。主线继续完整预算，固定验证CE与这些行为分开观察。

## 第8000/8500步：验证改善与单题生成反复

两次均使用协议v2、显式BOS、同一固定512条验证子集。CE从2.088454降到2.076738；第8000步“首都是”生成北京并EOS，第8500步则继续重复并出现“北京的首都是东京”。同一时期AI应用探针较连贯，水的三种状态仍答非所问和重复。原始输出保留于正式run对应的evaluation文件。

这组证据反驳“验证CE每次下降就意味着每一道问题都更好”。这是首轮预算约14.5%的中间模型，还不能判断最终能力或宣布已收敛；也没有因此改解码参数来掩盖重复。继续同时观察训练/验证分布目标和固定生成案例，最终比较统一协议的完整探针。

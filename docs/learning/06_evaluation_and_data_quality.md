# 第六课：评估的是哪种能力，数据问题又会怎样进入结果

评估接收固定权重、固定样本与固定推理协议，输出可复查的逐样本结果和汇总指标。一次forward成功、一个较低loss、几个顺眼的回答，分别只能回答很有限的问题。本课结合实际数据审计和早期模型结果说明边界。

## teacher forcing 与自己生成不是同一个条件分布

AR验证用真实前文预测下一个token，logits为`[B,T,V]`，比较`logits[:,:-1]`与`labels[:,1:]`，忽略`-100`。先累加每批CE×有效标签数，再除以总标签数；不能让10个标签的一批与1000个标签的一批权重相同。正式预训练的固定512条验证样本有123,368个标签，第3000步CE为2.36035，而初始为8.89428。

自由生成则把模型刚生成的token接回前文，错误会改变下一步输入。第3000步仍有冒号和短语重复等失败，因此CE下降不等于能可靠回答。`evaluation/step_0003000.json`同时保留CE和全部生成文本，没有只挑一个成功样例。

更低CE可能意味着更擅长局部语言模式；事实、指令遵守、长程依赖、推理、生成时的分布偏移，还要分别观察。AR token CE可以取指数得到相同tokenizer/数据口径下的perplexity，但这不是正确率。**Omni的text CE＋八路audio CE均值＋STOP加权＋aux，更不能整体取exp后冒充普通语言困惑度。**

## 选择checkpoint与最终测试

训练中的512条验证样本采用固定seed，从全held-out split抽取。每个保存点用同一子集选best；最终另算全部验证集，而不是把样本集改变造成的分数变化当作模型提升。源码见`lab/train.py`的`evaluate`、`update_best`。

这仍然是validation：我们反复看它、用它选checkpoint；最终全验证还包含那512条，因此不是完全未参与决策的独立test。后续做公平Full Attention/Hybrid比较时，要共享数据、评估协议与新增训练预算，保留相同起点和选择规则；不能比较一个多训几天的模型与另一个只适应几步的模型，然后把差异都归于架构。

保存的FP16模型导出与恢复用FP32权重也要区分。评估必须记录具体权重SHA、模型源码、tokenizer、prompt协议、precision、cache、sampling、max_new_tokens和EOS，而不只写一个checkpoint文件名。

## 小型学习探针能说明什么

`evaluation/text_probes_v1.json`在跑结果前固定，包含自然续写、算术、严格JSON、简短解释、代码和多轮指代。`tools/evaluate_text_probes.py`保留逐条输入、原始token、带/不带special token的输出、耗时、EOS与重复度。

算术的exact match同时测正确答案与“只输出结果”的格式遵守；正确答案藏在一长段解释中，不会被算成格式成功。JSON须真正解析且值相符；普通解释/代码先做定性阅读，不给一个虚假的自动高分。重复度也不是通用质量分数：合理重复和病态循环需要结合文本判断。

这些少量自拟题不是标准benchmark，不能证明未见知识或通用智力。CPU FP32与GPU BF16的贪心输出也可能不同，比较时固定执行协议。本工具的pretrain提示显式加BOS，与正式训练早期历史生成日志的无BOS协议不同；两组结果必须带标签保存，不能把更换提示包装说成训练进步。

官方参考权重单独保存在`data/reference_models/minimind_3_moe/`，固定来源/revision/SHA见`data/manifests/official_moe_references.json`；仅用于结构和评估校准，不是我们从零训练的权重。官方训练预算并未由这些文件完整给出，因此参考输出不是同预算架构消融结果。

## 相同对话、相同音频与相同训练样本

SFT全量5,109,432条，额外完全重复conversation有200,514条，最大重复831次。最高频组多为工具调用格式数据，实际示例见`reports/sft_duplicate_examples.json`。相同原始conversation的hash固定在同一split，避免这类完全重复跨train/val；不能据此声称做了语义去重。

A2A的414,024条记录只有172,348种不同conversation，但一条多模态样本还含输入音频、输出codes、声纹和参考音频。相同文本可能对应不同声音，不能只按conversation去重就宣称“提高质量”。这会改变声学条件和训练分布，必须先检查模态字段。

完整输入音频审计发现245,837种不同编码音频资产，其中12种在train与val的不同conversation中共享；249种验证音频里有12种已出现在训练侧。原有conversation划分不是严格的未见音频划分。后续应分别报告共享资产与未见输入资产上的结果，并对图像做相同检查。exact bytes检查也不等于感知去重：重新编码的相同声音可能有不同hash。

后续全量索引检查已完成，见 `reports/omni_multistage_overlap_v1/`。原451条A2A验证中31条涉及共享输入音频、61条没有输入音频；其余359条形成额外的未见音频评估组，覆盖237个未见资产。没有将验证数据挪回训练，也没有把无音频的文本混合记录视为坏数据。保留原完整验证用于阶段连续比较，额外分组专门回答未见录音条件下的表现。它仍不保证未见说话人或未见问题语义。

同一报告检查了T2A验证对语言SFT训练、A2A验证对前两阶段训练、I2T新视觉验证对前三阶段训练：完整conversation的hash交集均为0。这是有限的正面证据；问题单独重复、回答单独重复、语义近重复以及纯文本预训练里的知识均未被此检查排除。

Omni七阶段来源纠错后，又补查“后续训练是否污染早期回归评估”。`reports/omni_multistage_overlap_v2_forgetting/` 包含语言SFT、T2A、A2A、I2T视觉、I2T完整混合共5组train/val的25项组合，完全相同conversation的交集均为0。阶段6语音回训和阶段7视觉再对齐仍可沿用这些固定验证索引观察遗忘/恢复；上述语义与预训练污染限制仍然成立。

`lab/omni_loss.py` 在验证时额外输出每条样本的文本NLL和标签数、八路音频加权NLL和标签数、STOP数量及命中数量；`lab/omni_train.py` 将它们连同原始行号写入 `evaluation/*_rows.jsonl`。训练目标不变。`tools/summarize_omni_evaluation_cohort.py` 依据索引筛选记录，先累加分子与分母再计算分数；不能简单平均每条样本的CE。未完整覆盖目标分组时默认报错；周期抽样只能显式标为partial，不能冒充359条全评估。

实际验证：`tests/test_omni_loss.py` 对照原数学目标及logits梯度，并用单独forward检查选定样本的分组统计；均通过。`models/03_omni_moe/runs/trainer_cpu_per_record_v3/` 的真实训练器、小CPU模型、真实T2A数据、dropout、重计算和双worker中断/恢复，参数、AdamW、cursor、RNG全部一致，最终逐样本记录也逐字节相同。按记录重算完整验证与原汇总的selection score差异约9.47e-8，来自浮点累加顺序；这不是质量变化。该CPU测试验证逻辑，完整315M验证仍以GPU预检和正式结果为准。

## 截断是数据语义问题，不是只有显存问题

SFT在1536长度保留约86.86%的原始监督token，2003条训练行截断后没有答案标签，因此读取时显式过滤，实际预算变成5,102,028条、3,050,341,350个监督token。完整统计与原始口径在`reports/sft_data_audit.md`。这比“文件读完了一轮”更接近实际发生的优化。

音频输入更容易误判：SenseVoice的fbank长度决定文本流里重复的audio marker数量，输出Mimi则是每秒12.5帧、每帧8路codes；两个时间尺度不同。A2A输入原始最长92.304秒，官方变速可能再延长到约1/0.7倍。真实长尾检查出现2192个fbank位置，已经超过1536窗口，还没给回答留位置。

`reports/omni_a2a_batches_v1/`检查48条随机样本加16条特意选出的长样本、每条两个epoch增强。128次构造中7次完全没有监督标签；因为长尾被过采样，不能把7/128当作全量发生率。T2A另有均匀2048条检查，768长度两种epoch下分别13/16条缺少某路STOP，1536则为0/1条，也只是样本统计。

显存offload不会恢复被截掉的回答。处理长例时应先识别输入、目标和模板各占多少位置，再选择更长上下文、长度分组或明确的数据筛选/截断策略，并记录损失的覆盖范围；不能无声丢弃困难样本后声称全量质量更好。

## 本次应当怎样读结果

先看数据与标签覆盖，再看模型/训练预算和loss口径，接着看固定验证、独立探针与失败样例，最后结合吞吐/资源成本比较方案。当前只有第一项正式预训练在推进；Hybrid和Omni的检查证明系统路径的部分正确性，不能称为已经训练出有能力的模型。每个实验都以其config的purpose、实际token计数和evaluation为准。

## 已发现的视觉划分反例

I2T原按对话hash的验证集里，2929条仅15条使用未见图像资产。当前已按实际输入图像和重复对话的连通分量重新划分，保留606个未见视觉资产、2513条视觉验证记录；另有198条文本验证。旧分数留作原划分证据，不能和新分数直接比较。详见[数据诊断008](../debug/008_i2t_split_and_placeholders.md)。这是为何要先定义泛化问题，再设计train/val。

## 本项目的真实反例：两轮完成不等于质量通过

2026-10-06的Hybrid实验完成113,082步，固定验证CE降至1.6642，但生成仍会循环解释、算错并写错函数。同题官方AR参考也不是全对；因此我们补做同一held-out子集CE、相同GPU推理协议、CPU FP32和加长输出预算，保留全部原始文本。

这次要学会分开五件事：训练预算是否用完；checkpoint能否完整恢复；给定真实前文时的token预测目标是否改善；自由生成是否完成用户任务；评分是否把格式要求与事实正确性混在一起。例如144÷12算出12但附加长解释，会在“只输出数字”的精确评分下失败，不能等价于不会算这题。反过来，输出自然EOS但写17＋25=227，仍是明确的事实错误。

同时注意比较的分母：最终1066条CE=1.6381与固定512条CE=1.6642不属于同一个验证集合；官方基座可能见过这些记录，参考对照不能冒充未见数据benchmark。最后将FP16导出重新加载到FP32同集评分，量化导出差异约0.00038，再与官方基座1.3075作有边界的比较。

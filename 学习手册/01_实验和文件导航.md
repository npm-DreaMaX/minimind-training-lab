# 01 先弄清：我们在训练什么，手里有什么

这套课程使用一次真实的模型训练实验作案例。你不需要先会机器学习，但要逐步学会区分：数据、模型结构、参数、训练程序、训练结果。否则打开几百个文件，只会看到文件名。

本章结束时，你应能用自己的话讲清楚本实验的来历，并根据文件证据回答“做了什么、没做什么”。后续章节才沿着一条数据走进模型和优化器。

## 1. 模型是什么？权重又是什么？

先把模型想成一个有大量可调数字的函数：

```text
输入一段文字对应的编号 → 按模型结构计算 → 给接下来可能出现的 token 打分
```

**结构**规定怎么计算，例如先做注意力、再经过哪个专家。**参数/权重**是计算中可以被学习调整的数字。205M 的 M 表示百万：这里共有 205,623,072 个独立参数，而不是 205M 条数据、205M 个词或 205M 个文件。

仅有源码，好比知道计算公式，但里面的参数还没有设成训练好的值。仅有权重，也需要对应的模型类和配置才能解释它们。再加 tokenizer，才能知道输入文字对应哪些编号、输出编号对应哪些文字。

因此，用模型至少要把下面四样对应起来：

| 对象 | 本项目例子 | 作用 |
|---|---|---|
| 模型源码 | `models/02_hybrid_moe/src/model_hybrid.py` | 定义计算顺序 |
| 模型配置 | 正式 config 的 `model` 字段 | 决定层数、宽度、是否使用专家等 |
| tokenizer | `upstream/model/` | 文字与编号互相转换 |
| 权重 | `best_validation.pth` | 给模型中的参数赋值 |

`.pth` 是文件后缀，不是“保证能聊天”的认证。这份文件保存的是参数字典，必须先构造相应模型再加载，不能随便交给任意模型类。

## 2. 训练到底在改变什么？

以问答为例，训练程序读入用户问题及示范答案，让模型预测答案中的后续 token，计算预测与示范的差距，再调整参数。它并不是每读一条记录，就把那条记录原样存进一个可查询的资料库。

一次完整更新有这样一条因果链：

```text
数据 → 编号和目标 → 模型预测 → loss（差距）
→ gradient（参数变化会怎样影响差距）
→ optimizer（按梯度和历史状态决定更新）
→ 新参数
```

这些词现在先认识位置即可。第 02 章解决数据，第 03 章解决模型计算，第 04 章把梯度和更新逐步算给你看。

**推理**是用已有参数回答问题，通常不修改参数。**训练**则把计算出的学习信号用于参数更新。模型执行过 forward，甚至计算过 backward，都不自动表示已经训练更新；要看 optimizer 是否实际执行了更新。

## 3. 五个容易混在一起的词，要分别问

看到“全参数训练了两轮”，仍然不知道整个实验是什么。你需要继续问：

| 问题 | 可能的答案 | 这次 Hybrid 的答案 |
|---|---|---|
| 结构是什么？ | Dense/MoE，Full/Hybrid | 6 层 Gated DeltaNet、2 层 Full Attention，各层 FFN MoE |
| 参数从哪来？ | 随机初始化、继承已有模型、部分转换 | 继承官方 198M SFT 模型，替换六层注意力 |
| 用什么目标训练？ | 预训练、SFT、偏好优化等 | 对话示范的 SFT |
| 更新哪些参数？ | 全参数、只更新新模块等 | 所有模型参数可训练 |
| 学了多少？ | 样本、轮数、有效 token、更新次数 | 两轮，113,082 次更新，735,833,934 个有效监督 token |

“全参数”只回答更新范围，不表示从零；“两轮”只回答数据遍历次数，不表示每个知识都学会了。

## 4. 我们的 205M Hybrid 是怎样来的？

真实来源链是：

```text
官方已经训练好的 198M 普通 MoE SFT 权重
                 ↓ 复制形状与名称兼容的参数
保留两层 Full Attention、词嵌入、FFN 专家等
                 ↓ 六层注意力改为新的 Gated DeltaNet
新增模块随机初始化，组成 205M Hybrid
                 ↓ 官方 mini 对话数据，两轮全参数 SFT
当前交付的 Hybrid 权重
```

迁移时继承了 187,798,656 个参数，新建 17,824,416 个参数。它们相加是 205,623,072。来源见[迁移报告](../models/02_hybrid_moe/runs/transfer_official_sft_today_v1/transfer.json)。

新旧模块都输出 768 维向量，所以可以连接起来，但它们计算的内容不一样。把接口接通只能证明结构兼容，不能保证原来的能力保留。第 03 章会解释为什么随机替换少部分参数，也可能影响后面几乎所有层。

**这条分支没有进行 Hybrid 架构下的预训练。** 另一个普通 MoE 从零预训练分支中途停止，没有接入这个最终 Hybrid。旧的“只训新增模块”适应短分支也没有接入最终权重。目录放在一起不表示训练阶段自动相连。

## 6. 怎样读一份 recipe，而不只是背数字？

recipe 是训练配方：结构、数据、初始化、优化方法和系统配置的组合。打开[正式配置](../models/02_hybrid_moe/configs/hybrid_sft_official_mini_2ep_v1.json)，先找这些字段：

| 字段 | 实际值 | 现在先理解成什么 |
|---|---|---|
| `model.hidden_size` | 768 | 每个位置在网络内用多少个数表示 |
| `model.num_hidden_layers` | 8 | 顺序通过多少个主模块 |
| `model.use_moe` | true | FFN 使用多个专家与路由 |
| `init_weight` | 转换初始化权重路径 | 从哪些已有参数开始 |
| `corpus` / `stage` | token 缓存 / sft | 数据从哪读、按什么监督方式处理 |
| `batch_size` / `seq_len` | 16 / 768 | 一批记录数、每条位置数 |
| `accumulation_steps` | 1 | 累积几批梯度才更新 |
| `epochs` | 2 | 遍历训练集几轮 |
| `learning_rate` | 0.00001 | 优化器更新尺度的基准 |
| `checkpointing` | true | 此处指激活重计算，不是保存磁盘权重 |

配置不是全部答案。比如没写 `weight_decay`，训练器使用默认 0.01；没写 `betas`，默认 0.9、0.999。应把 JSON 和[lab/train.py](../lab/train.py)中读取默认值的位置一起看。

这里还有一个词义陷阱：`activation checkpointing` 是省激活显存的重计算技术；磁盘 `checkpoint` 是保存训练状态。第 05、07 章分别讲，不能因为都有 checkpoint 就混为一谈。

## 7. 一个 run 文件夹，是一份实验档案

正式 run 位于 `models/02_hybrid_moe/runs/hybrid_sft_official_mini_2ep_v1/`。不要一开始读完全部文件；按要回答的问题打开：

| 文件/目录 | 它能回答什么？ | 它不能单独证明什么？ |
|---|---|---|
| `config.json` | 计划按什么配置运行 | 是否真的执行完 |
| `source/` | 当时实际保存了哪个版本源码 | 算法必然正确 |
| `metrics.jsonl` | 每次更新记录了什么数值 | 未记录的逐位置激活 |
| `gpu.csv` | 采样时的显存、利用率、温度、功耗 | 某一瞬间完整的显存组成 |
| `evaluation/` | 指定时刻的验证与生成样例 | 每一步都做过评估 |
| `checkpoints/` | 保留哪些权重与恢复点 | 每个 step 都有可恢复文件 |
| `status.json` | 最近发布的运行状态 | 对应 PID 此刻仍活着 |

“能读到 status”与“训练正在进行”是不同判断。本课程主要读已经发生的历史记录，不会因学习命令自动恢复停止的训练。

## 8. 代码是谁写的，为什么要保留 diff？

`upstream/` 保存锁定版本的官方主线。`sources/` 保存作者实验及相关来源。`models/*/src/` 保存本实验使用的模型修复版；`lab/` 是我们自己的训练系统。来源版本见[provenance.json](../sources/provenance.json)。

diff/patch 是逐行记录修改前后的文本。它能告诉后来的人：哪一处来自官方，哪一处是实验兼容性修复，哪一处是自己的设计。它不能证明修改正确；正确性需要前向、梯度、更新或数据字节对照。

例如修复 Top-1 router 的梯度会改变反向传播行为，必须解释；更换日志文件名则通常只影响记录。后面会用真实案例练习这种区别。

# 10 自己动手：从能复述，到能计算、核对和诊断

读完九章不是自动毕业。你要完成下面的练习，留下自己的预测、实际结果、解释和证据路径，再用一道没背过的变化题检验理解。每项都写清“这次真正做了什么”，避免把看过报告当成亲自跑过同样实验。

本章使用三类材料：标准库小数字演示；真实训练历史只读重放；可选的完整205M CPU推理/梯度追踪。小数字例不会被算进正式训练，历史重放不恢复任何训练。

## 0. 先准备环境，分清命令在哪里执行

在你自己的仓库根目录打开终端，这个目录应能看到 `README.md`、`tools/`、`学习手册/`。其他电脑先按[分享指南](../SHARING_GUIDE.md)克隆；不需要作者的D盘路径。

```bash
python --version
python -B tools/lesson_examples.py --help
python -B tools/study_minimind.py --help
```

某些系统命令叫python3，请相应替换。不要把整段Python源码直接当shell命令执行：章节中的Python代码可保存为自己的`.py`文件再运行，或放进Python交互环境；`python tools/...`才是终端命令。

| 练习能力 | 需要什么 | 是否要下载大文件 |
|---|---|---|
| 读书、看PNG/CSV | 文件查看工具 | 不需要模型权重 |
| attention/delta/moe/optimizer/resume算术，summary/replay | Python标准库 | 不需要 |
| sample解码 | 分享指南的CPU依赖 | 不需要完整语料/权重，仓库带真实样本 |
| 完整模型trace/infer | CPU依赖及可用主存 | 需要421MB推理权重，不需要全量语料 |
| 精确恢复最终训练 | 完整状态、环境、语料及原配置 | 公共推理Release不包含全部恢复资产，本课程不启动恢复 |

`study_minimind.py`不创建optimizer，不更新参数。`lesson_examples.py`的optimizer/resume仅计算临时单标量的学习过程；第04章的PyTorch小例也只操作教学变量。都不会把新结果写回正式checkpoint。

为每个练习建自己的记录，四栏即可：**我的预测 → 实测输出/文件 → 解释差异 → 能否说明限制**。输出选新目录，工具拒绝覆盖已有答案。

<summary>核对答案</summary>

## 2. 把一条真实样本解释到每个位置

**先预测。** 用户不作为目标，是不是从输入中删掉了？507个token为什么要变成768位置？一个label为25是否表示第25步？

```bash
python -B tools/study_minimind.py sample --index 51023
```

**只先看四处。** `shape`、`nonpadding_input`、`valid_shifted_labels`，以及`first_80_positions`里的位置22–25。长文本可以后读。

**自己画配对。** 在纸上写出位置22的输出配哪个label，再解释输入位置、token编号和预测目标位置的区别。

<details>
<summary>核对答案</summary>

单条shape为[768]，507个非pad输入，261个pad，457个有效shift目标。用户仍在输入中提供上下文。位置23是ID25的think标记，由位置22的logits预测；位置24换行由位置23预测。51023是训练子集索引，缓存row51081，原始行51082，都不是optimizer step。

</details>

**变化题。** 如果把T截到助手第一个目标出现之前，labels会怎样？应该先调LR吗？答：会没有有效目标，应检查截断/模板与过滤规则，不是先调LR。

## 3. 手算一次attention和一次记忆更新

**先预测。** 第03章attention例中，把未来value改成999，当前位置该不该改变？Delta例中旧状态2、保留0.5、写入0.5、新value6，更新到多少？

```bash
python -B tools/lesson_examples.py attention
python -B tools/lesson_examples.py delta
python -B tools/lesson_examples.py moe
```

先自己算，再看输出。给attention的每个权重解释来源；给delta的每一步解释负责遗忘、已有预测还是纠错；给MoE的辅助项解释分母和层数。

<details>
<summary>核对答案</summary>

attention权重约[0.66976,0.33024,0]，结果[1.33952,1.32095]；正确因果遮挡下改未来不影响结果，取消遮挡约输出[999,999]。Delta为1+0.5×(6-1)=3.5；下一次保留和写入均为1时更新到6，不是9.5。均衡Top-1 aux单层0.0005，八层0.004。

这些是简化算术，证明你理解机制，不证明完整GPU kernel已通过所有形状测试。正式结构与对应验证见第03、08章。

</details>

**变化题。** 将delta的β设为0，仍会发生什么？答：不纠错写入，但α仍会改变旧状态。不要把“没写入”误作“状态完全不变”。

## 4. 区分loss、梯度与更新，检查一个真实反向链

先运行：

```bash
python -B tools/lesson_examples.py optimizer
```

写下w、loss、梯度、m、v以及更新后的w。特别观察算出梯度但尚未更新时，w是否改变。再手算100与900有效标签的加权CE。

<details>
<summary>小例答案</summary>

初始w0、正确概率0.5、CE约0.693147、grad=-1；仅算梯度不改w。教学AdamW用lr0.1更新后w约0.1，CE约0.598139。两个批次CE2/1、标签100/900时，总体应为1.1，不是1.5。实际Hybrid峰值lr1e-5，不使用教学lr。

</details>

想看真实完整205M的内部张量，先安装CPU依赖、获取权重：

```bash
python tools/fetch_learning_assets.py weight
python -B tools/study_minimind.py trace --index 51023 --length 128 --out 学习手册/实操输出/我的梯度检查_01
```

它在CPU加载完整模型并反向，可能需要数GiB可用主存，不使用训练GPU，不执行optimizer更新。若当前机器资源不足，可以先读已执行的[完整模型trace](实操输出/完整Hybrid梯度检查_v2/trace.json)，并在自己的记录里明确“本次阅读既有证据”，不冒充重跑。

**读文件的顺序。** 先找`input_shape`、`logits_shape`、`valid_labels`；再比较`ce`与`manual_ce`；再看`shapes`中的八层与router；最后看位置梯度，区分CE-only与总loss。

<details>
<summary>完整模型检查答案</summary>

输入[1,128]，hidden[1,128,768]，logits[1,128,6400]，router[128,4]。105个有效目标；CE与重算均约0.53979373，aux约0.00567702，总参数梯度norm约17.93575。23个不直接监督的前缀位置仍有CE输入梯度。没有optimizer更新，磁盘权重不变。

这不是完整T768验证，也不是GPU kernel数值对照，不能拿该loss作为新的能力成绩。

</details>

## 5. 自己列显存账本，再选一次调整

**任务。** 对205,623,072参数，计算FP32参数、梯度和两份moments；再算B16T768的一份BF16 logits。最后回答B4×G4怎样保持有效样本batch，又有什么不保证相同？

不需要故意把机器撑到OOM。先在纸上画“第二个累积小批”的共存对象，再读真实Omni失败记录。

<details>
<summary>核对答案</summary>

基础四类合计3.064GiB，一份BF16 logits150MiB。还未计全部激活、临时缓冲、分配器与其他进程。B4×G4与B16×G1同为每更新16条，但有效token要加权，MoE aux分组和随机性不保证完全相同。缩T则改变监督覆盖，不能只称显存优化。

</details>

**变化题。** 首步通过、次步OOM，为什么？Adam moments首步建立后常驻；累积还会叠加已有梯度。需要阶段采样验证，而非仅靠这个解释直接宣告根因。

## 9. 写两份能够被别人复核的debug报告

**报告A，真实现象。** Hybrid固定CE下降，仍有算术和任务执行错误。按第08章写候选原因、已做检查、排除范围、尚未排除的原因和下一项最有区分力的实验。

**报告B，教学故障。** 两个labels都是-100，mean CE得到NaN。说明有效目标数、分母、应检查模板还是截断、采用什么过滤/跳过规则、是否改变预算。

<details>
<summary>评分依据</summary>

A应引用cache/full-forward、CPU/GPU、输出预算与导出重载的实际证据，并承认还不能唯一归因架构或训练预算。B应定位“无有效目标”，不能以调LR或NaN置0代替处理；该小例不是正式Hybrid事故。

两份报告都应区分现象、假设和已证实原因。不给证据、同时改五个变量、声称一个检查排除所有bug，都不足以通过。

</details>

## 10. 设计一项你尚未执行的新实验

选一个明确问题，例如“同一官方Full起点，Hybrid转换后直接SFT，与Full同预算继续SFT有什么区别”。不要同时把数据、结构、LR、epoch都改掉。

你的方案至少写清：

| 项目 | 必须回答的问题 |
|---|---|
| 假设 | 什么结果支持它，什么结果反驳它？ |
| 主要变化 | 两边究竟只比较哪项？还有哪些无法完全一致？ |
| 来源与数据 | 权重/tokenizer/数据版本、划分、污染限制是什么？ |
| 目标与预算 | 监督哪些位置，多少有效token，多少更新？ |
| 系统配方 | B/T/G、precision、重算、offload怎样依据测量选择？ |
| 正确性 | 数据、forward/backward、关键梯度、resume怎样验？ |
| 评估 | 同协议CE、任务指标、原始回答、吞吐与显存怎样记录？ |
| 异常处理 | NaN、OOM、数据错误发生时怎样保留现场与停止？ |
| 成本与解释 | 同token与同时间预算怎样分别解释？ |

这个练习提交的是可审查方案，不会执行新训练。当前普通MoE停止决定保持不变。

## 11. 怎样判断学到了，而不只是看完链接？

按五项分别验收：

- **能说清**：不用原文解释数据、结构、目标、状态和预算。
- **能算出**：算attention权重、一次梯度、token加权loss、显存量级。
- **能定位**：在实际源码找到labels、shift、aux、backward、step和save。
- **能验证**：重放日志，复算数字，区分教学结果和正式结果。
- **能诊断**：面对一项未背过的变化，提出可以区分原因的检查，而非随机调参。

如果某项失败，回到对应章节和例子，不需要把整本从头抄一遍。自己的记录应明确哪些亲手做过、哪些只看过现成证据。

完成这些，说明你能围绕本次Hybrid SFT案例阅读与分析训练系统，并开始设计可解释实验。它不等于已经亲自完成从零大规模预训练、分布式训练、正式RL或Omni全部阶段；这些需要另外的源码核对与实际训练经验。

所有现成演示结果在[课程机制演示](实操输出/课程机制演示_v2/results.json)，独立PyTorch核对在[pytorch_checks.json](实操输出/课程机制演示_v2/pytorch_checks.json)。真实模型梯度和推理结果保留原目录，均标明范围。

你可以一次执行标准库演示并保存自己的新副本：

```bash
python -B tools/lesson_examples.py all --out 学习手册/实操输出/我的机制实验_01
```

不要从“命令返回0”推导“自己全懂了”。先关掉答案，独立解释一个变化，再打开实际结果核对。

# 10 自己动手，证明已经理解

以下命令在自己的仓库根目录执行，先按[分享指南](../SHARING_GUIDE.md)建立环境。已有答案保留在`实操输出/`，你先独立预测，再看答案。**这组工具不包含optimizer.step，不启动正式训练，也不恢复已停止的MoE。** 梯度追踪会运行完整205M的CPU forward/backward，临时占主存；序列裁成128是教学观测窗口，不是改写正式训练预算或模型结构。

```bash
python -B tools/study_minimind.py --help
```

## 1 找到真正的模型与来源

运行`python -B tools/study_minimind.py summary`。写出参数量、来源权重、六层替换、已训练目标、总更新和监督token；指出哪一个文件能推理、哪一个能完整恢复。

**答案：**205,623,072参数；官方198M SFT来源；六层Gated DeltaNet随机初始化，两层Full保留；两轮全参数SFT，无Hybrid预训练；113,082更新、735,833,934监督token。推理用`best_validation.pth`，完整恢复用`training_resume.pt`，统一入口在[最终交付](../models/02_hybrid_moe/deliveries/20261006_final_integrity_v1/README.md)。后者保留FP32参数、AdamW、RNG、cursor/config；不能用FP16推理导出冒充精确续训文件。

## 2 把一条真实数据解释到每个位置

运行`python -B tools/study_minimind.py sample --index 51023`。先猜：token是字还是词？为什么user标签为-100？位置23由哪个logit预测？原始JSON在哪？

**答案：**token是词表编码单元，不能固定等同汉字或词；完整解码判断文本，单token的替换符未必代表损坏。该训练样本对应缓存row51081、原始文件第51082行。位置23是监督token `<think>`，由logit位置22预测。user作为上下文，但其对应next-token目标不直接计CE。数据到labels详见[第02章](02_数据到Batch.md)。

## 3 读懂一次真实更新

运行`python -B tools/study_minimind.py replay --step 1`，再查12000、56541、56542和113082。比较epoch、cursor、LR、有效token、显存、最近一次评估。不要把最近保存的评估误认为“这一更新现场生成”。

**答案：**每轮56541次更新；第56541步结束首轮，第56542步进入第二轮。首步B16×T768名义12288位置，非PAD输入9228，有效shift标签7818；CE约10.653、aux约0.004540，裁剪前grad norm约45.811，实际更新前裁到1。最后batch只有4条；不能按每步恒定16条来估总记录数。

## 4 亲眼看完整模型的forward/backward

已执行结果：[trace.json](实操输出/完整Hybrid梯度检查_v2/trace.json)。你可以换一个**尚不存在**的输出目录重做；工具拒绝覆盖已有结果。

```bash
python -B tools/study_minimind.py trace --index 51023 --length 128 \
  --out 学习手册/实操输出/我的梯度检查_01
```

先填shape：input `[?,?]`、hidden `[?,?,?]`、logits `[?,?,?]`、router `[?,?]`。解释为什么训练模式下启用aux、但没有参数更新。

**实测答案：**`[1,128] → [1,128,768] → [1,128,6400]`；每层router `[128,4]`；105个有效shift标签。手算与模型CE均为0.53979373，aux0.00567702，参数grad norm17.93575。23个无直接监督的前缀位置仍有embedding输出梯度，因为它们影响后面的回答。没有创建optimizer；磁盘权重SHA前后相同。

这是最终FP16导出重载FP32后的CPU教学检查；不能把这个短样本CE与正式GPU全验证CE比较，也不是GPU kernel等价测试。

## 5 计算显存和有效batch

题：205623072参数，FP32参数、梯度和两份Adam moment，最低训练状态多少GiB？B16、accum1改为B4、accum4是否自动完全等价？

**答案：**`205623072×16 / 1024³ ≈ 3.064 GiB`，尚未算激活、logits、临时buffer、allocator和CUDA context。两个batch设定都是每更新16条，但有效token不同的microbatch要加权，MoE aux归一化和随机性可能影响轨迹；不能只把loss无条件除4。若sequence变了，监督预算也可能变，不属于纯工程等价。

## 6 用曲线解释现象

打开[训练图](图表/02_完整训练曲线.png)和[GPU图](图表/03_GPU资源曲线.png)。分别回答：训练CE波动是不是失败？grad norm大于1是否裁剪失效？GPU利用率高能否说明算法高效？墙钟跨度是否等于计算时间？

**答案：**先对照样本、有效token与固定验证趋势；逐批CE不要求单调。记录的是裁剪前norm，大于1正常。GPU忙可能在重计算、padding或低效kernel上；看有效label吞吐和profile。实际更新计时累计约47.58小时，首末墙钟约71.52小时，存在休眠/时钟异常，不把所有间隔强行归为同一种原因。

## 9 写一份真正的debug报告

题：“Hybrid的验证CE降了很多，但144÷12答0，是否证明Gated DeltaNet没有用？”按[第08章](08_评估和Debug.md)模板写现象、假设、检查、证据、排除范围、结论和下一步。

**参考：**不证明结构无用。本次随机替换后直接SFT，缺少Hybrid预训练与匹配Full续训对照。CPU缓存对照、CPU/GPU推理和长输出检查降低了部分推理bug假设的解释力；并未证明训练无数值/分布问题。应区分转换损伤、数据/目标、优化与结构，设计一次只改一个因素的对照。结论应写“未恢复基座表现，唯一根因未确定”。

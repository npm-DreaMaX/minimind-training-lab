# 09 把模型、目标、数据和系统连成一体

这一章是整个训练体系的地图，不是“这些阶段我们都已经训过”。本项目实际完成的主案例是Hybrid转换后的两轮SFT；普通MoE预训练中途停止；Preference/RL和dLM没有完成正式训练。

## 先区分四个独立问题

**模型结构**决定如何处理上下文：Dense/MoE决定FFN，Full/Gated DeltaNet决定注意力，视觉/语音编码器决定模态接口。**训练目标**决定奖励什么预测：AR下一个token、SFT回答、偏好排序、奖励最大化或掩码去噪。**数据和预算**决定学什么、学多少。**执行系统**决定怎样在设备上高效且正确地算出更新。

因此MoE不是一种训练阶段，Hybrid不等于RL，dLM不是把AR生成速度调快的开关。也不能把五种研究方向拼在一起就称作更强模型。

## 各阶段输入、输出和数学目标

| 阶段 | 数据输入与关键shape | 目标与输出 | 源码/本项目状态 |
|---|---|---|---|
| Tokenizer训练 | 原文本；学习词表/编码规则 | 将文本映射为离散ID，不训练LLM能力 | [官方脚本](../upstream/trainer/train_tokenizer.py)；本项目复用官方6400词表 |
| AR Pretrain | 文本token `[B,T]`，绝大多数非PAD位置监督 | `-mean log p(x[t+1] | x[:t+1])`；通用语言基座 | [自有训练器](../lab/train.py)；198M从零开始，停于13209步 |
| SFT | 对话模板、token/labels `[B,T]`；仅选定回答位置监督 | 同样next-token CE，条件和监督位置不同 | [本次配置](../models/02_hybrid_moe/configs/hybrid_sft_official_mini_2ep_v1.json)；Hybrid完整两轮 |
| DPO | 同一prompt的chosen/rejected；拼接后 `[2B,T]` | 提高相对于参考模型的偏好答案对数概率差 | [官方DPO](../upstream/trainer/train_dpo.py)；未训练 |
| PPO | prompt → 策略采样 → reward/value/log-prob | 优势加权的策略更新、clip/KL、value目标 | [官方PPO](../upstream/trainer/train_ppo.py)；未训练 |
| GRPO/CISPO | 每prompt采样G条，reward `[B,G]`、token log-prob `[B*G,R]` | 组内相对优势；两种不同的重要性权重处理 | [官方GRPO/CISPO](../upstream/trainer/train_grpo.py)；未训练 |
| Agentic RL | 含工具动作、工具返回与最终答案的轨迹 | 从交互结果计算reward；只给正确的策略位置回传 | [官方Agent训练](../upstream/trainer/train_agent.py)；未训练 |
| Dense dLM | 随机mask的token `[B,T]`、噪声概率、可监督位置 | 双向上下文恢复**同位置**原token，按mask概率加权 | [作者训练器](../sources/experimental/dlm/train_dlm_author.py)；只有完整Dense合同检查 |

表中的公式是核心目标；MoE aux、掩码、长度归一化和正则项必须继续看具体实现，不能凭阶段名字猜。

## 偏好训练为什么不是“继续喂好答案”

DPO中，设`Δπ = log π(chosen|prompt) - log π(rejected|prompt)`，参考模型为`Δref`，则`L = -log sigmoid(β(Δπ-Δref))`。参考模型冻结；policy可训练。当前官方实现先把回答有效位置log-prob**求和**成序列分数，再算这个目标，并加MoE aux。序列求和与token平均不是同一个目标，长短回答的处理需要检查。

SFT只告诉模型示范答案，DPO还告诉它在同prompt下哪个更好。若偏好标注混乱、只偏爱长回答、训练集泄漏，loss下降同样不保证质量。指标需要包含chosen/rejected margin、偏好准确率、长度、参考偏离和独立任务评估。

RL额外引入“模型自己生成数据”。Rollout很慢、包含采样随机性，还要保存采样时的old log-prob。GRPO用同题G条reward的均值和标准差构造advantage；所有回答同分时几乎没有相对学习信号，reward均值上升也可能是钻评分规则漏洞。

当前[GRPO脚本](../upstream/trainer/train_grpo.py)的奖励含长度、think格式、重复惩罚和reward model分数；不能称作纯数学正确性奖励。其GRPO分支使用clipped surrogate，CISPO分支将截断的重要性比值detach后乘advantage与当前log-prob。这是**算法变化**，不是两个速度选项。做RL前还应分别记录reward各分量、KL、advantage方差、生成长度、clip比例和吞吐。这里没有实际RL曲线，不能补画一张假结果。

## dLM改变的是哪些东西

作者Dense dLM与AR有相同参数形状，因此AR state_dict可严格加载；但因果可见性改为双向，目标从右移预测改成同位置去噪，生成从左到右改成多轮填mask。它仍需适应训练，加载成功不能当作转换完成。

损失为`sum(masked CE / p_mask) / 全部eligible位置数`。本项目实测了未来可见性、手算loss、梯度，并保留全无监督导致NaN、生成残留mask的反例。详见[真实dLM实验](../docs/learning/07_ar_and_masked_diffusion.md)。不能把它的去噪loss取exp后与AR perplexity直接排名。

## 下一次Full与Hybrid怎样公平比较

**问题A：相同从零预算，Hybrid和Full哪个更好？** 两者从初始化开始；共享tokenizer、数据清单、分割、采样顺序、长度和有效监督token预算；保留各自合理但预先声明的结构。约198M与205M并非完全等参数，须明确。报告实际FLOPs/用时和参数量；固定token预算与固定用时预算回答不同问题，不可能都天然相等。重复seed才能估计随机性。

**问题B：已有Full模型能否便宜地转换为Hybrid？** 共用官方起点，保留未转换基座和继续SFT的Full对照，再比较直接转换SFT、先适应后SFT等方案。替换6层时随机模块约17.82M，虽然占比不大，却改变了几乎全网的上下文传播。必须记录missing/unexpected keys、初始化和新增模块梯度，不能只报load成功。

本次完成的是问题B中的一个候选，缺少同预算Full续训等对照，且评估结果与生成样例已记录。它不能证明Hybrid架构比Full差，也不能证明从零Hybrid一定更好。官方基座可能见过本次留出数据，当前验证是迁移诊断，不是干净泛化榜单。

**下一轮若重新授权训练**，应先明确研究问题和验收指标，再安排控制变量。不要用机械加epoch代替假设，也不要把手动修正过的探针答案喂回训练后继续声称是独立评估。当前没有启动新实验。

## 工程优化与算法变化的判断

| 修改 | 应怎样判断 |
|---|---|
| 提前分词、数据mmap、无损分片 | token、label、顺序完全相同才是数据管线优化；本项目保存过字节/数值对照 |
| activation checkpointing | 重新算激活；随机性与数值路径一致时目标不变，但仍需梯度验证 |
| CPU moment offload | 状态搬家；更新算术/顺序和精度一致才可称等价；占RAM和传输 |
| batch减半、accum翻倍 | 有效batch可相同；须正确按有效token加权，aux/RNG/最后batch也要审计 |
| sequence缩短 | 改变上下文与被监督内容；属于recipe变化，不能只说省显存 |
| BF16、TF32、fused kernel | 目标通常相同，实际数值不同；先验证敏感梯度，再谈提速 |
| 换数据、去重、重采样、改LR/epoch | 改训练分布或更新轨迹；必须记录预算与语义变化 |
| Full改GDN、FFN改MoE、AR改dLM、GRPO改CISPO | 架构或目标变化，必须有独立实验名和对照 |

练习：给“相同token预算、同一数据、从零Full与Hybrid”的实验写验收表，至少包含质量、系统资源、恢复一致性、数据污染四类；不要把“能跑完”作为唯一标准。

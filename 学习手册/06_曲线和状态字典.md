## 核心字段逐个读

| 字段 | 单位/含义 | 观察方法 |
|---|---|---|
| event | train/evaluation等 | 先按事件区分，不能把所有JSON行都计作一次更新 |
| step | 已完成optimizer次数 | 检查连续性；113082步并非113082条样本 |
| epoch / cursor | epoch从0开始；本轮已消费记录数 | 完成时epoch2、cursor0；中间第1轮epoch为0 |
| ce_loss | 当前累积组token加权CE | 单步波动与batch难度有关 |
| aux_loss | 各层MoE辅助损失之和 | 结合分层路由，不把小aux当能力强 |
| loss | CE＋aux | 验证只算CE，比较时先对齐口径 |
| grad_norm | 裁剪前全局L2范数 | 大于1可正常；非有限、连续爆增或长期接近0需定位 |
| learning_rate | 本次实际更新用的LR | 核对step偏移和resume位置 |
| valid_tokens | 本步有效右移标签数 | 累加应等于tokens_trained |
| nominal_tokens | B×T等名义输入位置 | 含pad和不监督位置，不是有效训练量 |
| nonpad_input_tokens | 输入非PAD位置 | 包括用户、模板、助手 |
| input_padding_fraction | 1−非pad/名义 | 高padding浪费算力，调整packing会改变语义，不能悄悄做 |
| unsupervised_fraction | 1−有效标签/名义 | 含用户、pad和shift等，不是坏样本比例 |
| step_seconds | perf_counter包围一次更新 | 不含后面的周期评估/保存；不同于墙钟总用时 |
| valid_tokens_per_second | 有效标签/更新秒 | 比较时保持口径与样本分布一致 |
| cuda_allocated/reserved/peak | 字节 | 除以2³⁰得GiB；peak为进程高水位 |
| router_first_microbatch_nonpadding | 部分step的首microbatch统计 | 不是每一步/全部microbatch的全局统计 |
| time | Unix墙钟秒 | 曾出现睡眠/时钟调整，不能盲目差分当纯计算 |
| wall_seconds | 本次进程启动后的墙钟累计 | resume会重新起算，不是完整项目总时间 |

## 以真实第一步为例

step1：CE10.652998，aux0.004540，总loss10.657538，grad norm45.8114，LR1e-5，7818有效标签，约2.147秒。第一步速度包含冷启动影响，不适合直接外推全部时间。

两轮最后一批只剩4条；原始labels累计仍精确为735,833,934，既没有drop_last，也没有为了凑满batch重复最后记录。固定验证CE从10.7034下降到1.6642，说明token预测改善；生成质量另读第08章。

## 任意step怎样重放

```bash
python -B tools/study_minimind.py replay --step 1
python -B tools/study_minimind.py replay --step 12000
python -B tools/study_minimind.py replay --step 113082
```

这读历史文件，不运行训练。它返回该步状态和此前最近一次保存的评估；没有每步生成样例，也没有每步checkpoint。不能要求用一个不存在的中间权重重跑原始生成。

完整激活与逐参数梯度没有在每一步落盘；那样会产生巨大存储与同步开销。保留的是训练指标、指定里程碑和完整恢复点。第04章通过同源码的只读forward/backward让你观察内部张量，不能把这次教学观测说成当时每一步的快照。

## 状态与实际进程

`training`是最后发布的状态，不保证PID现在活着；`complete`只表示该run预算/流程结束，不代表质量合格；`paused`表示保存了可恢复状态，当前普通MoE已由用户决定停止，不能据此自行恢复。

本项目SIGTERM在optimizer边界保存，所以停止请求后可多完成正在执行的一步。完整文件写入、导出、绘图与进程退出需要时间。先核对日志、status、checkpoint保存记录和GPU锁，再判断“是否已经停了”。

练习：比较同一步的nominal、nonpad、valid三种token吞吐；说明为什么不能挑最大那个数字宣传训练速度。
